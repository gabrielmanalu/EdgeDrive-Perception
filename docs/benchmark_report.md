# Benchmark Report

Full benchmark data is in [`benchmarks/results/`](../benchmarks/results/).
This document provides context and interpretation.

---

## Test Conditions

```
Hardware  : Jetson Orin Nano Super 8GB (67 TOPS)
JetPack   : R36.4.7 | CUDA 12.6 | TensorRT 10.3.0
Clocks    : sudo jetson_clocks (CPU 1728 MHz, GPU 1017 MHz)
Dataset   : 404 nuScenes Mini CAM_FRONT images
Preloaded : All images in CPU RAM before timing
Duration  : 60s sustained run
```

## Key Findings

### 1. TRT inference is identical between Python and C++

```
Python TRT INT8 : 3.5ms
C++ TRT INT8    : 3.5ms
```

Same engine, same GPU — same result. This confirms correct C++ implementation.
The C++ speedup comes entirely from eliminating Python overhead.

### 2. C++ preprocessing is 3.3× faster

```
Python preprocess : 5.6ms (PIL/NumPy under Python GIL)
C++ preprocess    : 1.7ms (OpenCV letterbox, pre-allocated Mats)
```

Key C++ optimizations:
- Pre-allocated `cv::Mat` buffers (no per-frame heap allocation)
- Direct write to `cudaHostAlloc` pinned memory (no intermediate copy)
- `letterboxed_.setTo()` reuses existing buffer

### 3. Python INT8 is slower than FP16 despite faster TRT

```
Python FP16 : TRT 4.2ms + postprocess 1.2ms = 87.6 FPS
Python INT8 : TRT 3.5ms + postprocess 3.2ms = 78.5 FPS
```

Ultralytics processes INT8 output tensor with additional steps vs FP16.
Postprocess regression: 3.2ms (INT8) vs 1.2ms (FP16) = +2ms overhead.
Not a model issue — absent in the C++ decoder.

### 4. Power scales with throughput

```
FP32  (29 FPS)  : ~9.9W   ← low throughput, GPU underutilized
FP16  (87 FPS)  : ~11.0W  ← high throughput, more work/second
INT8  (78 FPS)  : ~9.7W   ← INT8 ops more power-efficient
C++   (193 FPS) : ~12.2W  ← max throughput, GPU fully utilized
```

All formats remain well under Jetson Orin Nano Super's 15W TDP.
No thermal throttling observed during any 60s run. GPU peak: ~58°C.

### 5. Single image vs 404 images (C++ only)

```
Single image : 193.0 FPS
404 images   : 193.3 FPS
```

Unlike Python, C++ shows identical throughput on single vs multi-image.
Python single image was faster due to caching; C++ preprocessing runs
the same code path regardless of image content.
